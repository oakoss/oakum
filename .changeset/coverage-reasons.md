`check`, `status` and the pull-request comment say how each changed package is covered. `check` prints a `coverage:` count and one line per way packages are covered: a bump file and its level, a `none` entry, a commit under commits-only intent, or commits that release nothing with their types (`refactor, test`); an empty bump file is named once as covering every changed package. An uncovered package names the path its change took, each commit on the branch asking to release it (short hash, subject, and its type: `fix`, `feat, breaking` or `not conventional`), the `oakum add` command that covers it at the highest level those commits ask for, and the `oakum add --none` command for a change that should release nothing. `check --json` carries this per package under the coverage look's `changed`, and `status --json` and templates as the top-level `changed` (`covered_by`, `via`, `released_by`, `fix`); where a document has `changed`, its `uncovered` is read from it. `status` and the comment list uncovered packages one per line with their path, the commits asking for a release and the `oakum add` command those commits imply, and a change that releases nothing under "Changed, releasing nothing".
